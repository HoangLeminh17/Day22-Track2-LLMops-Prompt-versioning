SECTION 29 - EVALUATION-ALIGNED REFERENCE FACTS
==================================================

The following facts are written to align retrieval quality with the lab's
50 evaluation questions and reference answers. They restate the required
answers in compact, retrieval-friendly form.

1. The three main types of machine learning are supervised learning,
unsupervised learning, and reinforcement learning.

2. Overfitting occurs when a model learns the training data too well,
including noise, and then generalizes poorly to new data.

3. The bias-variance tradeoff means high bias leads to underfitting and
high variance leads to overfitting. Good models balance both to minimize
total error.

4. L1 and L2 regularization reduce overfitting by adding penalty terms to
the loss function and discouraging overly complex models.

5. Cross-validation splits data into multiple folds to estimate model
performance more reliably.

6. Backpropagation computes gradients of the loss with respect to each
weight by applying the chain rule of calculus.

7. Convolutional Neural Networks are primarily used for grid-like data such
as images.

8. LSTM networks address the vanishing gradient problem through gating
mechanisms that control information flow over time.

9. Common neural network activation functions include ReLU, sigmoid, and
tanh.

10. Pooling layers in CNNs reduce spatial dimensions, lower computation,
and retain important features.

11. The transformer architecture uses self-attention and processes entire
sequences in parallel. It was introduced in "Attention Is All You Need"
in 2017.

12. Word embeddings represent words as dense vectors so that semantically
similar words are geometrically close in vector space.

13. Transfer learning in NLP means pre-training large models on massive
corpora and fine-tuning them on downstream tasks.

14. BERT handles language understanding with bidirectional transformer
training, masked language modeling, and next sentence prediction.

15. Self-attention lets a transformer weigh the importance of different
tokens relative to one another in the same sequence.

16. GPT is trained autoregressively to predict the next token from previous
tokens using very large text datasets.

17. Instruction tuning is fine-tuning a pre-trained language model on
instruction-following datasets to better align it with human intent.

18. RLHF stands for Reinforcement Learning from Human Feedback. It uses
human preference data to align models to be helpful, harmless, and honest.

19. Chain-of-thought prompting encourages models to reason step by step,
which can improve performance on complex tasks.

20. GPT-4 supports up to 128K tokens of context.

21. Retrieval-Augmented Generation combines a generative LLM with retrieval
from an external knowledge base so answers are grounded and more up to date.

22. The main components of a RAG pipeline are a retriever that searches a
document store and a generator that answers from the query plus retrieved
passages.

23. Dense retrieval uses neural embeddings to encode queries and documents
and typically scores relevance with cosine similarity or another vector
similarity metric.

24. Chunking strategy is important in RAG because it affects retrieval
precision and context-window fit. Common approaches include fixed-size,
semantic, and hierarchical chunking.

25. Advanced RAG techniques include re-ranking, query expansion, HyDE,
and iterative retrieval for multi-hop questions.

26. Vector databases are used to store and query high-dimensional vector
embeddings for fast similarity search.

27. FAISS is a library for efficient similarity search and supports exact
and approximate nearest neighbor algorithms.

28. Text embeddings capture semantic meaning by converting text into
numerical vectors where semantically similar texts are geometrically close.

29. HNSW is a hierarchical graph-based approximate nearest neighbor method
that enables logarithmic-complexity search in practice.

30. Hybrid search combines dense vector retrieval with sparse keyword
search such as BM25, often fused with Reciprocal Rank Fusion.

31. LangChain is an open-source framework for building LLM applications
with abstractions for chains, agents, retrievers, and data connections.

32. LangChain Expression Language, or LCEL, is a declarative way to
compose chains with the pipe operator and supports streaming, async,
and batching.

33. LangGraph extends LangChain for stateful, graph-based, multi-actor
applications and supports cycles.

34. LangChain memory types include ConversationBufferMemory,
ConversationSummaryMemory, ConversationWindowMemory, and vector store memory.

35. LangChain retrievers fetch relevant documents from a data source for a
query and commonly support vector stores and BM25-based retrieval.

36. LangSmith is a platform for debugging, testing, evaluating, and
monitoring LLM applications with automatic tracing.

37. LangSmith traces capture inputs, outputs, latency, token usage,
and errors across chain components.

38. The LangSmith Prompt Hub stores, versions, and shares prompt templates
and supports workflows such as A/B testing and rollback.

39. LangSmith helps monitor production LLM applications with latency
percentiles, error rates, token costs, and feedback annotations.

40. LangSmith datasets are used for systematic evaluation with example
inputs and expected outputs so teams can compare prompts or model versions.

41. RAGAS is an open-source framework for evaluating RAG pipelines with
LLM-based, mostly reference-free metrics.

42. RAGAS computes faithfulness by extracting claims from an answer and
checking whether each claim is supported by the retrieved context.

43. Answer relevancy in RAGAS measures how well an answer addresses the
question, often by generating synthetic questions from the answer.

44. Context recall in RAGAS measures whether the retrieved context covers
the information needed to answer the question, compared against a reference.

45. RAGAS evaluation typically requires user queries, generated answers,
retrieved contexts as a list of passages, and optionally reference answers.

46. Guardrails AI is an open-source framework for validating and adding
safety checks to LLM outputs with configurable on-fail actions.

47. PII means Personally Identifiable Information. Detecting it matters
because exposing it can violate privacy regulations such as GDPR and HIPAA.

48. Structured output validation ensures LLM outputs conform to expected
schemas such as JSON and can detect or repair invalid formats.

49. Constitutional AI gives a model explicit principles to follow and uses
self-critique or revision to improve responses.

50. Common AI safety concerns for LLMs include hallucination, toxicity,
bias, PII leakage, and jailbreaking attacks.
